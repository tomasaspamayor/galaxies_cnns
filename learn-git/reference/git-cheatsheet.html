Git command cheat sheet

The compressed essentials — print this and keep it beside your keyboard.

The three trees

Working tree

Files you edit on disk. State: modified.

Staging area (index)

Holds what the next commit will record. State: staged.

Git directory

Permanent snapshot database (.git). State: committed.

git add → staging  ·  git commit → git directory  ·  git restore --staged ← back to working tree

Short status codes — git status -s

Left column = staging area. Right column = working tree. A blank means "no change there".

CodeMeaning
 MModified in working tree, not staged
M Modified and staged
MMStaged, then modified again in working tree
A New file staged for the first commit
D  /  DDeleted (staged / unstaged)
R Renamed (staged)
??Untracked — Git has never seen this file

Look before you leap

$ git status -s          # compact: what is where
$ git diff                # working tree  ⇄  staging area
$ git diff --staged       # staging area  ⇄  last commit
$ git log --oneline --graph --all   # history as a picture
$ git show <commit>       # the changes in one commit

The everyday loop

$ git add <file>          # stage current content of a file
$ git add -p              # stage interactively, hunk by hunk
$ git commit -m "message" # record the staged snapshot
$ git commit --amend      # fix the LAST commit (local only!)
$ git commit -a -m "msg"  # stage all TRACKED files, then commit

Undo, safely

GoalCommand
Un-stage a file (keep edits)git restore --staged <file>
Discard edits in a file (destructive)git restore <file>
Fix the last commit message/add filesgit commit --amend
Undo a commit, keep the changesgit reset --soft HEAD~1
Undo a pushed commit (makes a new commit)git revert <commit>
Rule of thumb

Committed work is almost always recoverable. Uncommitted work that you restore or reset --hard away is generally gone. Commit early; stash instead of discarding.

Branching (Lesson 0002)

$ git branch                  # list branches (star = current)
$ git switch -c experiment     # create a branch and switch to it
$ git switch main              # switch to an existing branch
$ git switch -                 # jump back to the previous branch
$ git merge experiment         # merge a branch into the current one
$ git branch -d experiment     # delete a merged branch

checkout is the older spelling of switch/ restore. You'll see it everywhere: git checkout -b x = git switch -c x.

Stash — shelve work temporarily (Lesson 0003)

$ git stash            # shelve tracked changes, clean the tree
$ git stash -u         # ...also include untracked files
$ git stash list       # see the stack of stashes
$ git stash pop        # re-apply the newest stash and drop it
$ git stash apply      # re-apply but KEEP it on the stack

Tags — mark milestones (Lesson 0004)

$ git tag -a v1.0 -m "first working model"   # annotated tag
$ git tag                                   # list tags
$ git tag -a v0.9 9fceb02                    # tag an older commit
$ git push origin v1.0                       # tags are NOT pushed by default

Remotes

$ git remote -v              # where "origin" points
$ git fetch                  # download remote commits (don't merge)
$ git pull                   # fetch AND merge into current branch
$ git push -u origin <branch> # first push of a branch, set upstream
